# The application's secrets: the ONE place they are declared.
#
# Read by three things, so they cannot drift apart:
#   scripts/bootstrap.sh  creates each secret in Secret Manager and populates the
#                         `generate` ones (before the first `pulumi up`)
#   infra/pkg/secrets     grants the VM read access to each one, and passes this
#                         list to the VM as instance metadata
#   vm/bootstrap.sh       reads each value at render time and exports it as
#                         SECRET_<NAME> for the config templates, e.g.
#                         blog-acme-email -> ${SECRET_ACME_EMAIL}
#
# Pulumi never reads a value. Ids must start with "blog-".
#
# source:
#   generate  scripts/bootstrap.sh fills it with `openssl rand -hex 32` if it has
#             no version. Required: the VM refuses to render app config until
#             every one of these is readable, rather than starting the app with
#             an empty signing key. If the app needs a value in a specific
#             format (a JWT, a base64 key of fixed length), change
#             generate_secret() in scripts/bootstrap.sh for that id.
#   operator  created empty; you add the value by hand. Optional: rendered as
#             an empty string, with a warning, while it has no value.
#
# <secret-id>                 <source>
# A static site has no app secrets of its own.
# Caddy's ACME contact address. Special-cased by vm/bootstrap.sh into the
# Caddyfile's global `email` directive; a secret only to keep it out of the
# repository and out of instance metadata.
blog-acme-email              operator
